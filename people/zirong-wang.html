How I work

How I use AI

I use AI as part of a real development workflow, not just a code generator. I break an idea into small features, write clear specs and prompts, review the generated code, and test how everything fits together.

AI can write a lot of the code, but architecture, scope, and testing still need human judgment. That part is my job.

Building the first working version taught me that product and architecture decisions matter before adding more features.

A hard problem I cracked

The hardest part of Owl Jeopardy Phase 1 was keeping AI-generated code consistent as the project grew. Features like the game board, scoring, and Google sign-in were built at different times, so a change to login or game state could break something that already worked.

I fixed this by keeping the architecture and design docs up to date, testing each new feature against the rest of the app, and guiding the AI to fix integration problems without rewriting working code. By the end, the core game was stable enough for later phases to build on.
